================================================================================
  演習進捗ダッシュボード (Study Tracker) 制作手順 & 運用マニュアル
================================================================================

【概要】
Streamlit をフロントエンド、Google スプレッドシートをバックエンドDBとして
採用した、モバイル最適化・任天堂風UIの学習進捗管理Webアプリケーション。
端末の再起動やアプリの再デプロイを行ってもデータが保持される完全永続化構成。

--------------------------------------------------------------------------------
1. システム構成・技術スタック
--------------------------------------------------------------------------------
- フロントエンド / サーバー: Python, Streamlit
- バックエンド (データベース): Google Sheets (st-gsheets-connection / gspread)
- インフラ / ホスティング: Streamlit Community Cloud, GitHub
- スタイリング: CSS3 (Mobile-first, cubic-bezier micro-interactions)

--------------------------------------------------------------------------------
2. Google スプレッドシート設計
--------------------------------------------------------------------------------
Google ドライブ上にスプレッドシートを1点作成（例: study_tracker_db）。
シート（タブ）は以下の2枚を厳密な小文字名称で作成する。

■ シート1: `problems` (問題マスタ)
  - A1: problem_id   (問題の一意識別子: 例 EM-001)
  - B1: subject      (科目名: 例 電磁気学)
  - C1: unit         (単元名: 例 ガウスの法則)
  - D1: title        (問題名: 例 同軸円筒導体の電界)

■ シート2: `attempts` (演習履歴ログ)
  - A1: attempt_id   (履歴ID: 連番数値)
  - B1: problem_id   (対象問題ID)
  - C1: attempt_date (実施日: YYYY-MM-DD)
  - D1: is_correct   (正誤フラグ: 1=正解, 0=不正解)
  - E1: memo         (演習メモ / つまずきポイント)

※注意: スプレッドシート初期作成時、データが0行（ヘッダーのみ）だと
  pandas / gspread 側で空データ例外が発生する場合があるため、
  テスト用データを2行目に1行入れておくこと。

--------------------------------------------------------------------------------
3. セットアップ & デプロイ手順
--------------------------------------------------------------------------------

[Step 1] Google Cloud サービスアカウントの発行
1. Google Cloud Console にてプロジェクトを作成。
2. 「API とサービス」>「ライブラリ」から以下2つのAPIを有効化。
   - Google Sheets API
   - Google Drive API
3. 「認証情報」>「認証情報を作成」>「サービス アカウント」を作成。
4. 作成したサービスアカウントの「キー」タブから「鍵を追加」>「JSON」を作成し、
   秘密鍵 JSON ファイルをPCにダウンロード。

[Step 2] スプレッドシートの権限付与
1. JSON 内の `client_email`（サービスアカウントのメールアドレス）を確認。
2. 対象の Google スプレッドシートの「共有」設定を開く。
3. 上記メールアドレスを追加し、権限を「編集者」に設定して保存。

[Step 3] リポジトリ構成ファイルの準備
プロジェクトフォルダ内に以下のファイルを配置:
- `app.py`: アプリケーション本体
- `requirements.txt`: 依存パッケージ
    streamlit
    st-gsheets-connection
- `.gitignore`: 秘密情報の除外
    *.json

※注意: 秘密鍵 JSON ファイルは絶対に GitHub へ push しないこと。

[Step 4] Streamlit Cloud Secrets の設定
1. PowerShell 等で JSON ファイルから TOML 形式テキストを生成:
   python -c "import json; d = json.load(open('your-key.json', encoding='utf-8')); print('[connections.gsheets]'); [print(f'{k} = {json.dumps(v)}') for k, v in d.items()]"
2. Streamlit Cloud のアプリ設定 >「Settings」>「Secrets」を開く。
3. 生成した内容を貼り付け、先頭（[connections.gsheets] の直下）に
   スプレッドシートのURL行を追加して保存:
   
   [connections.gsheets]
   spreadsheet = "https://docs.google.com/spreadsheets/d/XXXXXXXXX/edit"
   type = "service_account"
   project_id = "..."
   ...

--------------------------------------------------------------------------------
4. 開発・トラブルシューティングで得られた重要知見（注意点）
--------------------------------------------------------------------------------

1. Markdownのインデントコードブロック誤認バグ
   - 現象: HTMLタグが解釈されず、画面上に生コードがむき出しで表示される。
   - 原因: CommonMark仕様により、4文字以上のスペース（字下げ）が存在すると
     「コードブロック（<pre><code>）」と判定される。
   - 対策: st.markdown に渡す直前に各行の先頭空白（インデント）を
     strip() 処理して除去する。

2. モバイル端末での画面縮小 & 上部見切れ問題
   - 現象: スマホでアクセスした際、カードが極小2列になり上部がヘッダーに隠れる。
   - 原因: layout="wide" によるPC前提の描画判定、および Streamlit 標準ヘッダー
     バーとの padding-top の干渉。
   - 対策: 
     * layout="centered" に変更。
     * Mobile-first（スマホを基準の1カラムとし、幅800px以上で2列展開）なCSS設計。
     * 上部余白を `padding-top: 4.5rem !important;` に拡張し、安全領域を確保。
     * iOS Safari のフォーカス時自動拡大（ズーム）を防ぐため、フォーム入力要素
       （input/select）のフォントサイズは 16px 以上を厳守。

3. Streamlit Cloud Secrets のエラー対処
   - エラー: `ValueError: Spreadsheet must not be None`
     → Secrets に `spreadsheet = "https://..."` の指定が抜けている。
   - エラー: `WorksheetNotFound: attempts`
     → スプレッドシート内のタブ名が一致していない（大文字小文字・スペース混入）。

--------------------------------------------------------------------------------
5. 日常の運用・バックアップ
--------------------------------------------------------------------------------
- アプリ画面からの登録・更新・削除はリアルタイムでスプレッドシートへ反映。
- 大量の問題登録や誤字修正は、Google スプレッドシートを直接開いて
  コピペ・一括編集しても問題なくアプリ側に反映される（ttl=0 設定のため）。
- 定期的に Google ドライブ上でスプレッドシートをコピー保存することで、
  容易に完全なバックアップを取得可能。
